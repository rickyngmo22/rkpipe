# rknn_eval 远程评测与数据集框架设计（含 PC 端操作指导）

> 状态：设计定稿，V0–V2.5 已实现；**V3 起部署形态改为板端服务**——
> 板端 `eval_web_service.sh start` 起控制台，PC 浏览器直连 `http://<板IP>:8081`
> 操作（Windows 零环境）。数据集主路径为**网页分选图片文件夹与标注文件增量同步**
>（webkitdirectory + 板上按文件夹缓存，二次评测只传差异图片；标注单文件直传）；
> Linux PC 可选 ssh 增量拉取（数据留 PC、结果回传 PC，setup-pc 配免密）；
> 小数据集可 zip 直传；PC 端 ssh/rsync 驱动（run_eval.py）保留为脚本化备选路径。
> 目标：通用模型评测框架——支持 COCO 官方数据集与用户自定义数据集
>（任意类别数、主流标注格式），网页可视化操作。

---

## 1. 总体架构

**核心原则：数据不动，动作动。** 大体积资产（图片、标注）留在 PC；
板端只承担 NPU 推理 + 检测导出（dump），评测计算与报告全部在 PC 完成。

```
┌──────────────────── PC / 浏览器 ────────────────────┐
│  Web 控制台（浏览器）                                │
│   ① 评测提交：任务/模型/数据集/参数                   │
│   ② 任务队列：进度条 + 实时日志                       │
│   ③ 报告中心：表格 + LaTeX + 可视化图 + 历史对比       │
│   ④ 数据集管理：注册/校验/预览标注叠加图               │
└───────────────┬─────────────────────────────────────┘
                │ HTTP (FastAPI, 默认 :8081)
┌───────────────┴────────────── PC ───────────────────┐
│  rknn_eval_web（Python，新增）                       │
│   · REST API + 任务队列 + 静态页面                   │
│   · 数据集注册表（datasets/*.yaml）+ 格式转换器       │
│   · 评测执行：调 rknn_eval（本地 或 --remote ssh）    │
│   · 报告渲染（report.md + summary_all.json + CSV）   │
└───────────────┬─────────────────────────────────────┘
                │ ssh / rsync（复用已有密钥，免密配置一次）
┌───────────────┴────────────── RK3588 ───────────────┐
│  rknn_eval（现有二进制，不改动）                      │
│   · 板端图片目录 → --dump-detections + metrics       │
│   · 新增 --dump-only：跳过评测段（评测在 PC 做）      │
└─────────────────────────────────────────────────────┘
```

**职责切分**：

| 位置 | 承担 | 不承担 |
|---|---|---|
| PC | 数据集存储/格式转换/评测计算/报告/Web 界面/任务编排 | NPU 推理 |
| 板端 | 推理 + dump 导出 + 流水线指标 | 标注解析、mAP 计算、报告 |

> 板端也装了 pycocotools，可作为无 PC 环境的降级路径（ssh 进板直接跑本地模式），
> 但主路径是 PC 评测——标注和数据集本来就在 PC。

## 2. 远程评测数据流（一次评测的完整生命周期）

```
[提交] 浏览器 POST /api/jobs {task, model_tag, dataset_id, conf, threads, compare[]}
   │
[队列] Web 服务调度（同板串行，多板可并行）
   │
[推图] rsync -a --info=progress2 <PC dataset>/images/ board:/tmp/rk_eval/<job>/images/
   │   （增量传输：第二次评测同一数据集只传差异）
[执行] ssh board "rknn_eval --task ... --model <板上路径> --images /tmp/rk_eval/<job>/images \
                  --dump-only --out-dir /tmp/rk_eval/<job>/out"
[回收] scp board:/tmp/rk_eval/<job>/out/{dump_*.jsonl,metrics_*.json} → PC runs/<job>/
[评测] python3 tools/eval/eval_coco.py --ann <PC 标注> --dump runs/<job>/dump_main.jsonl
[清理] ssh board "rm -rf /tmp/rk_eval/<job>"（可配置保留 dump）
[报告] report.md 渲染 → 浏览器报告页
```

**传输量对比**（以 COCO val2017 为例）：
图片 800MB（首次，之后增量≈0） vs dump ~60MB / 每次评测。
标注（20MB）、GT、转换产物永远只在 PC。

**断点与容错**：

- rsync 天然断点续传；job 状态机 `queued→pushing→running→pulling→evaluating→done/error`，
  每步落库（JSON 文件），Web 重启后可恢复展示（不自动重跑，人工点重试）。
  ✅ 已实现：run_eval.py `--state-file` 阶段落盘（含推图百分比/分批 i/n/模型序号），
  Web 启动时从 `web_runs/*/web_job.json` 还原历史 + 中断标记，CLI 产物
  （eval_runs/ 等）从 summary_all.json 合成条目，`POST /retry` 人工重试。
- rsync `--partial --timeout` 保留半截传输、空闲超时探测；推图/拉取瞬断自动重试 3 次。
- ssh ControlMaster 连接复用（整个 job 一条连接）+ ServerAlive 保活 + `accept-new`
  首连自动收 host key；`--remote-cwd` 固定板端执行目录（label 等默认相对路径依赖）。
- 板端进程被杀 → dump 尾行截断 → 评测脚本已逐行容错。
- ssh 断连 → job 置 error，日志保留，重试只补差异。

## 3. 数据集框架（通用，不预设场景）

### 3.1 数据集注册 schema（用户唯一需要写的东西）

`datasets/<name>.yaml`：

```yaml
# 示例 1：官方数据集（注册一次，板上已有图片的走 --board-images 复用）
name: coco_val2017
type: detect              # detect | obb | seg | pose
format: coco              # coco | yolo | voc | dota | yolo-obb
images: /data/coco/val2017          # PC 路径
ann: /data/coco/annotations/instances_val2017.json
# 可选：板上已有同样的图片目录（如 <仓库>/test_images）则跳过推图
board_images: <仓库>/test_images

# 示例 2：自定义 YOLO 格式（ultralytics 训练产物，工业最常见）
# name: my_defect
# type: detect
# format: yolo
# images: /data/defect/val/images
# labels: /data/defect/val/labels
# names: /data/defect/data.yaml    # 类别表来源；也可内联:
# names: [rust, dent, scratch]     #（yaml list）
# label_file: model/defect_labels_list.txt  # 模型 label 文件，用于顺序一致性校验

# 示例 3：旋转框（DOTA 原生 或 YOLO-OBB 四点）
# name: my_parts_obb
# type: obb
# format: dota            # 或 yolo-obb
# images: /data/parts/val/images
# labels: /data/parts/val/labelTxt
```

### 3.2 能力矩阵与转换器（注册表模式，可插拔）

| format | type=detect | type=obb | type=seg | type=pose | 转换器 |
|---|---|---|---|---|---|
| `coco` | ✅ | — | ✅ | ✅（需官方 kpts 文件） | 直通 + 合法性校验 |
| `yolo` | ✅ | — | — | — | `yolo→coco`（薄） |
| `voc` | ✅ | — | — | — | `voc→coco` |
| `dota` | — | ✅ | — | — | → `patches_gt.jsonl`（复用 split_dota） |
| `yolo-obb`（归一化四点） | — | ✅ | — | — | → dota jsonl |
| `labelme` | — | — | 计划 V3 | 计划 V3 | 多边形→RLE |

统一中间格式：水平框系 → **COCO JSON（任意类别数）**；旋转框系 → **DOTA gt jsonl**。
评测器（eval_coco.py / eval_dota.py）不感知来源格式。

### 3.3 类别表解析链与映射规则（去掉 COCO-80 硬编码）

解析优先级：标注自带 `categories` → YOLO `data.yaml names` → 模型 `label_file` → 注册内联 `names`。

评测时自动判定模型 cls id（0..N-1 连续）→ COCO category_id 的映射：

1. 标注 categories 的 id **恰好连续 1..N** 且顺序与类别表一致 → `cls+1` 直映射（自定义数据集常态）；
2. 标注为 **COCO 官方 80 类**（类别名命中内置表）→ 现有 `CONTIG80_TO_COCO` 空洞映射；
3. 都不满足 → 报错，提示检查类别表顺序（这是最常见的掉精度陷阱，宁报错不错评）。

### 3.4 数据集校验与预览（注册时自动执行）

- 图片数 vs 标注覆盖数（有多少图没标注——漏标预警）；
- 类别分布直方图（长尾可见）；
- bbox 合法性（w/h>0、坐标在图内、类别 id 越界）；
- **标注叠加预览**：随机 N 张画 GT 出图，人眼确认标注质量——复用 rknn_eval 的
  `--vis-dir` 渲染逻辑（画 GT 而非预测）。
- 校验结果存 `datasets/<name>.check.json`，Web 数据集页展示。

## 4. PC 端操作指导（目标使用方式）

### 4.1 一次性环境准备

```bash
# PC 侧（Linux/WSL/macOS）
pip install fastapi uvicorn numpy pycocotools opencv-python-headless pyyaml
# 评测脚本与 rknn_eval 源码树（tools/eval/）在 PC 上 git clone 本仓库

# 免密 ssh 到板（一次性）
ssh-copy-id user@<板IP>

# 板侧：确认 rknn_eval 就位（已在板端编译产出）
#   <仓库>/build/rknn_eval
# 模型预先 scp 一次（反复评测不重传）：
scp model/yolo26n.rknn user@<板IP>:<仓库>/model/
```

### 4.2 CLI 直用（不启 Web，脚本化场景）

```bash
# 注册数据集（写 datasets/my.yaml，见 §3.1）
# 转换 + 校验（yolo/voc 需要；coco 直通校验）
python3 tools/eval/convert_dataset.py --spec datasets/my_defect.yaml --vis 20

# 远程评测：一条命令（推图→板推理→拉 dump→PC 评测→报告）
python3 tools/eval/run_eval.py --spec datasets/my_defect.yaml \
  --board user@<板IP> \
  --model board:<仓库>/model/defect_y26n.rknn \
  --task detect --conf 0.001 --threads 4 \
  --compare fp16=board:<仓库>/model/defect_y26n_fp16.rknn \
  --out-dir runs/defect_y26n
```

`--model board:<path>` 表示模型已在板上；`--model <本地文件>` 则先 scp 上去。
数据集标注 `board_images` 未配置时自动 rsync 推图，已配置则直接用板图。

### 4.3 Web 操作（主路径）

```bash
cd <仓库>/tools/eval
python3 -m rknn_eval_web --port 8081        # PC 上启动
# 浏览器打开 http://<PC-IP>:8081
```

页面流：

1. **数据集管理**：填表注册（等价于写 yaml）→ 自动校验 → 看类别分布和
   标注叠加预览图 → 状态变为 Ready。
2. **评测提交**：选任务 → 选模型（下拉=板上 model/ 目录扫描，或上传）→
   选数据集（只列与任务 type 匹配的）→ conf/threads/对照模型 → 提交。
3. **任务队列**：卡片显示状态与进度（推图字节/推理帧数来自 metrics 轮询）、
   实时日志尾部、失败原因。
4. **报告中心**：主表 + 量化损失表 + 逐类表 + conf 扫描曲线；
   可视化图网格（--vis-dir 产物）；LaTeX 一键复制；CSV 下载；历史任务对比折线。

### 4.3.1 实时预览（推理结果实时显示）

三层实时粒度，板端除 `--preview` 开关外零改动：

| 粒度 | 机制 | 说明 |
|---|---|---|
| 数字实时 | ssh 流式读远程 stdout（每 100 帧一行进度），Web 每 2-3s 轮询 | 帧数 / FPS / 各阶段耗时 |
| 画面实时 | 评测命令带 `--preview`：打开引擎现成 web_preview（MJPEG，带叠加渲染），浏览器直接嵌板端流 URL | 浏览器可达板端 IP 时首选，本身就是实时的 |
| 快照轮播 | PC 端抓帧协程从 MJPEG 流每 5s 存 `preview.jpg`，浏览器轮询该图 | 跨网段 / 板端端口不便直达时的降级 |

- 提交页「实时预览」开关默认开；浏览器直连板端走画面实时，否则自动降级快照轮播。
- **不影响评测正确性**：dump 在叠加绘制之前写（后处理原始输出），预览不污染精度数字。
- **FPS 口径**：MJPEG 编码占少量 CPU，预览模式 FPS 低 ~5-10%；报告以关预览的
  metrics 为准，预览画面旁的 FPS 仅供参考。可选「基准跑关预览 + 预览对照跑」。
- **健康监控副产物**：模型/类别映射/数据集错误在画面上几秒内肉眼可见
  （框乱飞/无框/类别名不对），不必等全量跑完看报告。

**多模型对比时的预览行为**：`--compare` 为串行推理，预览**跟随当前正在推理的
模型**——任务卡片显示「正在推理: yolo26n (1/2)」，模型切换时流短暂重连并更新
角标。不做双模型实时分屏（pipeline 串行 + 双进程抢 NPU 会双双失真）。

**事后同图对比**（对比场景的主力工具）：每个模型跑完按 `--vis-sample N`
（每 N 帧渲一张，控制磁盘）渲染检测结果图；报告页「可视化对比」标签按文件名
对齐做**多模型并排网格**（同一张图，每行一个模型的渲染结果）——严格同图、
可暂停细看，比实时分屏更有说服力，也顺带成为错误样本排查入口。

### 4.4 板端资源约定

- 工作目录 `/tmp/rk_eval/<job_id>/`：图片 + dump，job 结束自动清理（保留项可配）。
- 板端存储有限 → 推图按数据集分批（默认 500 张/批，边推理边可删已推批，V1 先整集+清理）。
- 模型管理：板上 `<仓库>/model/` 为模型根，Web「模型」页扫描展示。

## 4.5 与 rknn-toolkit2 官方连板模式的对比与互补

本方案在拓扑上与官方连板模式（`rknn-toolkit2` 的 `init_runtime(target='rk3588')` adb/USB 转发、
`accuracy_analysis` 连板抓层）同构——数据在 PC、推理在板端 NPU、PC 控制。但定位不同：

| 维度 | 官方连板（toolkit2 target=板子） | 本方案（rknn_eval + ssh） |
|---|---|---|
| 通道 | toolkit2 内置 RPC 走 adb/USB | ssh/rsync 走网络，通用设施 |
| 执行方式 | 逐图 RPC：PC 喂一张、板推一张 | 整集批量上板，板端独立流水线跑完 |
| 传输开销 | 每张图一次 PC↔板往返 | rsync 批量压缩，二次评测增量≈0 |
| FPS 口径 | **失真**：含逐图 RTT、单线程、无流水线 | 板端原生部署链路（多线程/零拷贝/RGA），即真实部署性能 |
| 精度口径 | toolkit2/官方 demo 的 Python 前后处理 | 与部署**完全同一条 C++ 链路**（同后处理/预处理） |
| 数据集规模 | 几十~几百张量级 | 全量 val（COCO 5000 张约 2 分钟/模型） |
| 环境依赖 | PC 装 toolkit2+adb，版本与板端 runtime 强耦合 | PC 零 RKNN 依赖，只要 ssh |
| 板端改动 | 无（runtime 由 toolkit2 推送） | 预编译 rknn_eval（一次性） |

**定位**：官方连板是**开发调试工具**，本方案是**验收测量工具**，互补而非替代。

- 开发期：用 `accuracy_analysis` 抓每层量化前后输出，定位"哪一层掉精度"，
  回头调量化参数（如混合量化切层）——层级诊断能力本方案不覆盖也不打算覆盖。
- 交付期：用本方案出端到端数字。连板口径的 FPS/mAP 与最终部署的 C++ 程序不是
  一个运行环境，直接写进产品资料或论文是不严谨的；本方案口径 =
  板端部署程序 + 全量官方评测协议。

## 6. 关键决策记录

| 决策 | 选择 | 理由 |
|---|---|---|
| 评测计算位置 | PC | 标注在 PC；板端保持薄；pycocotools 装一次 PC 即可 |
| 板端改动 | 仅加 `--dump-only` | rknn_eval 其余逻辑复用；板端不做标注解析 |
| 远程通道 | ssh/rsync（非 HTTP 服务） | 零新协议、零鉴权面、断点续传、复用密钥；HTTP server 列为备选不实施 |
| 与 toolkit2 连板模式的关系 | 互补（调试 vs 验收，见 §4.5） | 连板口径含逐图 RTT/单线程，不能代表部署性能；层级量化诊断仍用官方工具 |
| 标注中间格式 | 水平框=COCO JSON，旋转=DOTA jsonl | 评测器零改动；转换器单向归一 |
| 类别映射 | 解析链 + 自动判定（§3.3） | 通用框架不假设 COCO-80；宁报错不错评 |
| Web 框架 | FastAPI + 原生 JS | 依赖少；无构建链 |
