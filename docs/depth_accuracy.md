# 深度与距离精度评估

> 状态：⚠️ **尚未完成实测标定**。本文档记录 2026-09-17 的分析过程、
> 已排除的方案、以及**唯一可靠的后续做法**。
>
> 关联：[`demo_detect3d.md`](demo_detect3d.md)（3D 线框）、
> [`demo_d3_depth_distance.md`](demo_d3_depth_distance.md)（距离文字显示）

## 为什么需要这份文档

`depth_dist_scale` 与 `depth_next_m`（近距告警阈值）目前都是**凭肉眼调**的：

- 线框比车大 → 调大 scale；比车小 → 调小
- 告警太频繁 → 调小阈值；不告警 → 调大

**没有「模型输出 vs 卷尺实测」的对照表，3D 线与距离告警的可信度都是悬空的。**

本文档就是为建立这张表而写——**目前只完成了前半部分：把不可行的路子排除掉**。

## 已排除的方案（★ 别再走一遍）

### ✗ 方案 A：2D 框像素高 × 先验车高反推距离

**已被实测证伪。**

> **2026-09-17 二次复核修正（重要）**：早期归因为「2D 框比车身松 3.8 倍」，
> **这个归因本身是错的**。基于 901 帧真实检测数据的复核表明 **框其实很紧**：
> 稳定轨迹帧间 `|Δ框高|` 中位数 **0.0px**（最大 3.0px）；
> 几何自洽性检查（出租车）宽法 Z=2.9m vs 高法 Z=2.7m，**相差仅 6%**——
> 两条独立标尺反推同一距离高度一致，说明框贴合真实车身。
>
> 早期「3.8 倍」来自**手工标注的框**，且拿「侧视车长投影」的预期去衡量**正后视车**，
> 预期本身就套错了车型姿态。
>
> **但方案 A 依然不可用**，理由换成了更本质的一条：未标定相机的 `fx` 未知，
> 且 2D 框只能约束「宽×高」面，无法确定车辆姿态（同一框宽可能是侧视的车长、
> 也可能是正视的车宽，两者差 2.4 倍）。**单框单目约束不了距离。**

| 量 | 实测值 | 应有值 | 备注 |
|---|---|---|---|
| 出租车 2D 框高（手工标注） | 310 px | 82 px（1.5m 车高 @ 11m） | 见上方修正：手工标注框不可靠 |

> **该表已作废。** 真实 YOLO 输出的框高与几何自洽性检查均表明框是紧的；
> 此表的两行数据都建立在手工标注框之上，不再作为论据。

### ✗ 方案 B：地面接地点反推距离

公式 `Z = h_cam · fy / (v_ground − cy)`（h_cam = 相机安装高度）在数学上正确，
但**要求 `v_ground` 是真实的车轮接地点**。

早期实测：用 YOLO 框底边（y=830）代入，得 Z = 3.99m —— 当时判为「明显偏小」。
**但 2026-09-17 复核推翻了「框底低 100+px」的判定**：真实检测数据显示
框底 y2 的 p50=747、p90=879，而同帧画面里框底确实贴合车轮接地/阴影处。
框底确实略低于真实接地点，但**幅度远小于早期判定的 100+px**。

**方案 B 依然不可用，但理由是**：`h_cam`（相机安装高度）本身未实测，
且 y2 是模型输出、受遮挡与阴影影响；没有 h_cam 与真实距离的对照，公式无法标定。

参考对照表（相机高 1.3m、cy=634.5）：

| 真实距离 | 接地点的理论 y |
|---|---|
| 5 m | 790.4 |
| 10 m | 712.5 |
| 15 m | 686.5 |
| 20 m | 673.5 |
| 30 m | 660.5 |

### ✗ 方案 C：地平线检测交叉校验 cy

原理正确（无 roll 时「地平线 y = cy」），但在本类素材上**失效**：
`baseline17.mp4` 中梯度法给 220、天空色法给 916.5，相差 692px。
原因：**城市峡谷 + 前车（公交车）遮挡**导致天空可见区域极窄且被切碎，
梯度法把公交车顶边缘误判为地平线。

工具 `tools/estimate_horizon.py` 现已加入自我诊断，分歧 >80px 时
明确报告「本素材不适用」而**不给假信心**。

## 唯一可靠的后续做法：卷尺实测

> **⛔ 当前状态：用户已确认无现场条件（2026-09-17），此路径暂时搁置。**
> `depth_dist_scale` 保持 **1.0 未标定**。
> 在无标定前提下，**距离文字只作相对参考，不可作绝对依据**。

需要**现场**做，无法从已有视频补出来：

1. 把车（或人）停在**确定的距离**上，用卷尺量，例如 5m / 10m / 20m / 30m；
2. 板端跑 `console_detector`，让目标出现在画面里，记下：
   - depth 模型输出的米数（`depth_dist_text` 显示，或加 `RK_PIPE_DEBUG_*` 打印）
   - 目标在画面里的**像素宽**（已知车型可查真实车宽）
   - 目标**车轮接地点**的像素 y（目视确认，不是框底）
3. 用工具算 scale：

```bash
python3 tools/calibrate_depth_scale.py --fx 599.87 --cx 990 --cy 634.5 \
    --known-width 1.8 --px-width 305 --model-depth <模型输出的米数> \
    --cam-height 1.3 --y-bottom <目视确认的接地点 y>
```

**必须多测几个距离**（近/中/远各一条以上）—— 只有一条样本无法区分
「scale 错了」和「那条样本本身有问题」。

4. 若不同距离给出的 scale 差异大（>30%），说明是**非线性偏差**（模型在不同距离上
   偏差比例不同），单靠一个 scale 修不好，需要在文档里记录**分段修正表**。

既然无法卷尺标定 scale，把力气转到**「不依赖 scale 也能改善」**的方向：

| 已做 | 内容 |
|---|---|
| ✅ 距离门限 | `detect3d_min_depth_m: 8.0`——近距车不画线框，消除溢出（不涉及 scale） |
| ✅ 排除手工标注框 | 确认模型自带的框是紧的（帧间抖动 0px），**不需要**做框收紧 |
| ⏸ 姿态自动判定 | 按框 AR 选 alpha（0°/90°）——但实测证明近距车换姿态只会把溢出换方向，价值有限 |
| ⏸ scale 标定 | 等有现场条件再做 |

## ⚠️ 一个重要提醒：改 scale 会同时影响距离文字和 3D 线框

`k = fx / depth_dist_scale` 是 3D 线框的**等效旋钮**：

- 改 scale `1.0 → 0.36` **等效于** fx 乘 `2.76`
- 所以调 scale 时，**距离文字和 3D 线框会同时变化**

这意味着：**不能一边用线框贴合度调 scale、一边指望距离文字自动变准。**
两者是耦合的。正确顺序是：

1. **先用卷尺把 scale 标定准**（距离文字可信）；
2. **再调 fx** 让线框贴合（此时 fx 是纯粹的线框形状旋钮，不影响距离）。

反过来做（先调线框再标距离）会陷入「两个旋钮互相干扰」的困境。
